🚀 Manual de Instalación

Esta guía te lleva desde cero a servidor corriendo con todos los servicios configurados: Supabase, Upstash Redis, OpenRouter, Trigger.dev, VAPID keys y webhooks SIEM. Cada sección incluye pasos exactos, qué verás en pantalla y resolución de errores comunes.

    B --> D["Upstash: crear Redis + token"]
    B --> E["OpenRouter: API key gratuita"]
    C --> F["pnpm db:push (migraciones)"]

3. Quick Start (5 minutos)

# 1. Clonar
git clone https://github.com/StrategicConnex/StrategicConnexAudit.git
cd StrategicConnexAudit

# 2. Instalar dependencias
pnpm install

# 3. Copiar y configurar variables de entorno
cp .env.example .env.local

# 4. Migrar base de datos (requiere DIRECT_URL configurada)
pnpm db:push

# 5. Iniciar servidor de desarrollo
pnpm dev
# → Abrir http://localhost:3000

4. Supabase — Base de Datos y Autenticación

4.1 Crear el proyecto

  1. Ve a supabase.com → Start your project.
  2. Inicia sesión con GitHub o email.
  3. En el dashboard → New project → nombre, contraseña, región y plan Free.
PasswordGuárdala en un gestor de contraseñas: se usa en DATABASE_URL y DIRECT_URL.

4.2 Obtener credenciales

  1. Project Settings → API: copia URL → NEXT_PUBLIC_SUPABASE_URL, anon public key → NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY, service_role key → SUPABASE_SERVICE_ROLE_KEY.
  2. Project Settings → Database → Connection string: URI (directo :5432) → DIRECT_URL; Pooler URI (:6543) → DATABASE_URL.

4.3 Configurar Magic Link

  1. Authentication → Settings → Site URL: http://localhost:3000 (dev) y https://scaudit.vercel.app (prod).
  2. Authentication → Providers → Email: habilitar email signup; Confirm email OFF (usamos Magic Link); Secure email change ON.

4.4 Ejecutar migraciones

pnpm db:push

Resultado esperado: listado de tablas (audits, projects, intelligence_*, security_audit_logs, siem_alert_logs, anomaly_detections, adversary_scenarios, plugin_packages, dns_history, whois_history, etc.) y Applied migrations.

Direct URLSi ves DIRECT_URL is missing, asegúrate de copiar .env.example → .env.local y llenar DIRECT_URL. Si tu password tiene @ # $, usa URL encoding (@ → %40).

5. Upstash Redis — Rate Limiting

  1. upstash.com → Create database → nombre scaudit-ratelimit, región cercana, Enable Global recomendado.
  2. En la pantalla de detalles copia REST URL → UPSTASH_REDIS_REST_URL y REST Token → UPSTASH_REDIS_REST_TOKEN.
curl -s -X GET "$UPSTASH_REDIS_REST_URL/ping" -H "Authorization: Bearer $UPSTASH_REDIS_REST_TOKEN"
# → {"result":"PONG"}

11. Dev Bypass Auth

Para desarrollo local: NEXT_PUBLIC_DEV_BYPASS_AUTH=true permite navegar el dashboard sin login, crear proyectos con usuario sintético y probar todo sin Magic Links.

NUNCA en producciónEl guard NODE_ENV === 'development' lo desactiva automáticamente en Vercel, pero no lo incluyas en las variables de entorno de producción.

13. Solución de Problemas

ErrorSolución
The "middleware" file convention is deprecatedNext.js 16 usa proxy.ts. Elimina src/middleware.ts si existe.
DIRECT_URL is missingCopia .env.example → .env.local y llena DIRECT_URL.
password authentication failedPassword con caracteres especiales → URL encoding; proyecto pausado → reactivar; usar :5432 directo en DIRECT_URL.
relation "xxx" does not existEjecuta pnpm db:push.
Failed to fetch en Magic LinkVerificar URL/anon key; Site URL incluye localhost:3000; env vars en Vercel.
eval() is not supportedLimpia caché de Turbopack: rm -rf .next && pnpm dev.
Both middleware and proxy detectedElimina src/middleware.ts.
